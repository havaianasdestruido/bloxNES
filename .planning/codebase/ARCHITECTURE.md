# Architecture

**Analysis Date:** 2026-05-03

## Pattern Overview

**Overall:** Client-Server with Shared Code (Roblox Standard)

**Key Characteristics:**
- Separation of client-side and server-side logic
- Shared codebase in `ReplicatedStorage`
- Early development stage (only "Hello World" prints exist)
- Reference implementation available in C++ (`src/SimpleNES/`)

## Layers

**Client Layer (`src/client/`):**
- Purpose: Handle user input, render NES screen, play audio
- Contains: `init.client.luau` (entry point)
- Depends on: Shared modules, Roblox GUI APIs, UserInputService
- Used by: Roblox client when player joins

**Server Layer (`src/server/`):**
- Purpose: Server-side logic (if any multiplayer features needed)
- Contains: `init.server.luau` (entry point)
- Depends on: Shared modules, Roblox game services
- Used by: Roblox server during gameplay

**Shared Layer (`src/shared/`):**
- Purpose: Code shared between client and server
- Contains: `Hello.luau` (example module)
- Depends on: Roblox APIs available in both contexts
- Used by: Both client and server

**Reference Layer (`src/SimpleNES/`):**
- Purpose: C++ implementation of NES emulator to port from
- Contains: CPU, PPU, APU, Mapper implementations
- Depends on: C++ standard library, SFML (original), miniaudio
- Used by: Developer as reference only (not part of Roblox game)

## Data Flow

**NES Emulation (Expected Flow):**
1. Player joins game (triggers `init.client.luau`)
2. ROM loaded from `ReplicatedStorage` or `rom/` directory
3. NES emulator initialized (CPU, PPU, APU, Mapper)
4. Emulation loop runs (frame-by-frame)
5. PPU output rendered to `SurfaceGui`/`ScreenGui` in Roblox
6. User input captured via `UserInputService` → NES controller
7. Audio generated by APU → Roblox sound objects

**Current State:**
- Only print statements exist, no actual emulation logic yet

## Key Abstractions

**Expected (Based on SimpleNES Reference):**
- `Emulator` - Main emulator controller (CPU + PPU + APU + Mapper)
- `CPU` - 6502 CPU emulation
- `PPU` - Picture Processing Unit (graphics)
- `APU` - Audio Processing Unit (sound)
- `Cartridge` - ROM loader and mapper detector
- `Mapper` (and subclasses) - NES memory mappers (NROM, MMC3, etc.)
- `Controller` - Input handling

**Current:**
- No abstractions implemented yet

## Entry Points

**Client Entry:**
- Location: `src/client/init.client.luau`
- Triggers: Player joins game, Roblox runs client scripts
- Responsibilities: Initialize emulator, set up rendering, handle input

**Server Entry:**
- Location: `src/server/init.server.luau`
- Triggers: Game server starts
- Responsibilities: Currently minimal (may handle multiplayer sync)

**Shared Modules:**
- Location: `src/shared/*.luau`
- Triggers: Required by client or server code
- Responsibilities: Shared utilities and emulator components

## Error Handling

**Expected Strategy:**
- Roblox uses `pcall()` and `xpcall()` for protected calls
- Errors can be caught and logged via `warn()` or `error()`
- No structured error handling yet

**Current State:**
- No error handling implemented

## Cross-Cutting Concerns

**Logging:**
- `print()` for basic output (currently used)
- Expected: `print()`, `warn()`, `error()` for different log levels

**Testing:**
- No testing framework detected
- Roblox has no built-in unit testing (third-party tools like TestService exist)

**Performance:**
- NES emulation requires ~60 FPS (16.67ms per frame)
- Roblox runs at ~60 FPS, so emulation must be efficient
- Lua/Luau performance considerations for 6502 CPU emulation
